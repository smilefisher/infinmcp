接入 infinmcp

请输入管理员分配给你的 API Key。Key 只保存在本机浏览器（localStorage），不会上传到别处。

还没有 Key？看「使用说明」里的「第一步」。

本页无需登录即可阅读。

这是什么

infinmcp 是一个只读数据库 MCP 服务，把 MySQL / Doris / Redis / MongoDB 的能力通过 MCP 暴露给 AI 客户端。 所有写操作（增删改、DDL、FLUSHALL、$out 等）都会被服务端拒绝，可以放心接入测试环境。

只读是硬限制：不是提示词约束，而是服务端的语法/命令白名单校验。写语句根本到不了数据库。

第一步：拿到 API Key

  • API Key 由管理员在配置文件 server.apiKeys 中分配，每人一个，并带角色：admin 或 user。
  • user：可以查询、可以看调用日志，不能改连接配置。
  • admin：额外可以在「连接」页新增 / 编辑 / 删除连接，并测试连通性。
  • 拿到 Key 后，在「连接」页填入即可（会记在本机，下次免填）。

第二步：把 MCP 客户端接进来

下面示例里的占位符都要替换成实际值：
  • <测试机地址> → 服务地址，如 127.0.0.1（本机）或 172.31.236.167（局域网）。尖括号不是合法主机名，原样保留会报 ENOTFOUND。
  • 8787 是默认端口，起服务时改过就跟着改。
  • /mcp 是固定路径，别丢、别改名。
  • <你的 API Key> → 实际 Key。
  • {env:INFINMCP_API_KEY}（Claude Code 里是 ${INFINMCP_API_KEY}）两种写法都行：保留并设置同名环境变量，或者直接填明文 Key。

先看：改的是哪个文件

客户端命令写入的文件生效范围
Claude Codeclaude mcp add … --scope user~/.claude.json（顶层 mcpServers）所有项目
Claude Code… --scope local（默认）~/.claude.json → projects["<目录>"].mcpServers仅该目录
Claude Code… --scope project<项目>/.mcp.json该项目（可提交）
OpenCode V2opencode mcp add … --global~/.config/opencode/opencode.json所有项目
OpenCode V2opencode mcp add …<项目>/opencode.json该项目
注意：project / 项目级作用域会把 API Key 明文写进项目文件。 项目要进 git 就改用 user / --global，或用环境变量占位（${VAR} / {env:VAR}）。

OpenCode（远程 HTTP）

{
  "mcp": {
    "servers": {
      "infinmcp": {
        "type": "remote",
        "url": "http://<测试机地址>:8787/mcp",
        "oauth": false,
        "headers": { "Authorization": "Bearer {env:INFINMCP_API_KEY}" }
      }
    }
  }
}

把 INFINMCP_API_KEY 放到环境变量里，避免把 Key 写进配置文件。

或者用命令行（推荐，自动写对文件和结构）：

opencode mcp add infinmcp --global \
  --url http://<测试机地址>:8787/mcp \
  --header "Authorization=Bearer <你的 API Key>"
两个坑： ① OpenCode V2 的 MCP 配置在 mcp.servers.<名字> 下（V1 是直接 mcp.<名字>，写成 V1 那样不生效）； ② opencode mcp add 不会自动加 oauth: false，而远程服务器默认走 OAuth —— 不补上，Key 一旦失效就会报出和 Claude Code 同款的 DCR 错，所以加完手动补一句 "oauth": false。

验证：opencode mcp list 看到 ✓ infinmcp connected，或会话里 /mcps 查看。 注意 mcp list 是按当前目录的项目上下文报告的，要在你实际使用 OpenCode 的目录下执行。 全局配置在 ~/.config/opencode/opencode.json（--global 写的就是它）， 不加 --global 则写当前项目的 opencode.json。 移除：删掉配置里那个条目（没有 remove 子命令）。

Claude Code

命令行一条搞定（下面用 user scope，所有项目都能用）：

claude mcp add --transport http infinmcp \
  http://<测试机地址>:8787/mcp \
  --header "Authorization: Bearer <你的 API Key>" \
  --scope user

加 --scope user 自己所有项目都能用（推荐，Key 也不会落到仓库里）； --scope project 写进项目根目录的 .mcp.json，适合团队共享但注意 Key 会进版本库； 不加则是默认的 local，只对当前目录生效。

加完要新开一个会话才生效（MCP server 在会话启动时加载）。工具名会带前缀： mcp__infinmcp__mysql_query、mcp__infinmcp__mysql_schema …； 移除用 claude mcp remove infinmcp --scope user。

或者手写项目根目录的 .mcp.json：

{
  "mcpServers": {
    "infinmcp": {
      "type": "http",
      "url": "http://<测试机地址>:8787/mcp",
      "headers": { "Authorization": "Bearer ${INFINMCP_API_KEY}" }
    }
  }
}
两个坑： ① type 必须写 "http"——只给 url 不给 type 时，Claude Code 会当成 stdio 服务直接跳过； ② ${VAR} 由 Claude Code 自己展开，不用手动替换。

验证是否接上：claude mcp list 看到 ✔ Connected，或在会话里输入 /mcp。 项目级配置首次使用会让你确认一次（安全提示），同意即可。

其它支持远程 MCP 的客户端（通用 JSON）

{
  "mcpServers": {
    "infinmcp": {
      "url": "http://<测试机地址>:8787/mcp",
      "headers": { "Authorization": "Bearer <你的 API Key>" }
    }
  }
}

不同客户端的字段名略有差异（有的用 transport / type），以客户端文档为准。

本机 stdio 方式（不用 HTTP，仅自己用）

{
  "mcpServers": {
    "infinmcp": {
      "command": "node",
      "args": ["/path/to/infinmcp/dist/index.js", "mcp", "-c", "/path/to/infinmcp.config.json"]
    }
  }
}

stdio 模式不校验 API Key，调用者记为 local；适合本机调试，不适合多人共用。

完整版接入说明（含各类客户端的字段差异、环境变量语法对照、排错对照表）： 服务端仓库的 docs/clients.md。

第三步：开始提问

接好之后，直接用自然语言问，客户端会自己选工具。例如：

  • 「列出所有可用连接」
  • 「main 库里 users 表有哪些字段？」
  • 「查一下 main 库最近注册的 10 个用户」
  • 「cache 里 user:* 有哪些 key？」
  • 「docs 里 orders 集合按状态统计条数」

调用示例

// MySQL：按 id 取一行（用参数占位，别拼字符串）
mysql_query
{
  "connection": "main",
  "sql": "SELECT id, name, created_at FROM users WHERE id = ?",
  "params": [1024]
}

// Doris：同样是 MySQL 协议，按时间聚合
doris_query
{
  "connection": "warehouse",
  "sql": "SELECT city, count(*) AS n FROM orders WHERE dt >= ? GROUP BY city ORDER BY n DESC",
  "params": ["2024-01-01"]
}

// Redis：读一个 hash
redis_exec
{ "connection": "cache", "command": "HGETALL", "args": ["user:1024"] }

// Redis：扫 key（cursor 为 "0" 表示扫完）
redis_scan
{ "connection": "cache", "pattern": "user:*", "count": 100 }

// MongoDB：查最近 5 条订单
mongo_find
{
  "connection": "docs",
  "collection": "orders",
  "filter": { "status": "paid" },
  "sort": { "createdAt": -1 },
  "limit": 5
}

// MongoDB：按状态分组统计
mongo_aggregate
{
  "connection": "docs",
  "collection": "orders",
  "pipeline": [
    { "$group": { "_id": "$status", "n": { "$sum": 1 } } },
    { "$sort": { "n": -1 } }
  ]
}

只读边界：这些会被拒绝

数据库会被拒绝替代做法
MySQL 多语句、INSERT / UPDATE / DELETE / DROP / ALTER、INTO OUTFILE、FOR UPDATE、EXPLAIN ANALYZE 只发单条 SELECT / SHOW / EXPLAIN / DESC / WITH
Doris 同 MySQL：多语句、INSERT / UPDATE / DELETE / DROP / ALTER、INTO OUTFILE、EXPLAIN ANALYZE 只发单条 SELECT / SHOW / EXPLAIN / DESC / WITH
Redis 写命令（SET / DEL / INCR / EXPIRE / FLUSHALL…）、CONFIG / CLIENT / DEBUG / EVAL / SCRIPT、阻塞与订阅类（BLPOP / SUBSCRIBE / XREAD / MONITOR）、KEYS 用 redis_scan 代替 KEYS
MongoDB 聚合写入阶段 $out / $merge（含嵌套），服务端脚本 $where / $function / $accumulator 把结果取回来自己在本地处理

返回值有行数上限（配置里的 limits.maxRows，当前值见「连接」页顶部）， 超出的部分会被截断并标注「已截断」。单次查询还有超时限制 limits.timeoutMs。

连接配置（管理员）

  • 只有 admin 能在「连接」页新增 / 编辑 / 删除连接，并点「测试」验证连通性。
  • 保存后立即生效，不用重启服务，MCP 客户端下一次调用就能用上新连接。
  • 编辑已有连接时，口令 / URI 留空表示沿用旧值，不用重新输入密钥。
  • 连接配置保存在服务端数据目录的 connections.json（权限 0600）。
  • 也可以写在服务端配置文件的 connections 里（那种方式改完要重启）； 同名时以 connections.json 为准。

口令建议用环境变量

配置文件的字符串值整体等于 {env:VAR} 时会替换成环境变量，缺失则启动即报错（不会静默用空口令）：

{ "password": "{env:MYSQL_PW}" }   // ✅ 会替换
{ "password": "pw-{env:X}" }       // ❌ 不是这个语法，按字面量处理

全局限制（所有连接共用）

配置默认说明
limits.maxRows200单次返回的最大行数 / 文档数，超出会标注「已截断」
limits.timeoutMs10000既作查询超时，也作连接超时

常见问题

提示 401 unauthorized

API Key 缺失或不正确。确认请求头是 Authorization: Bearer <key>（或 X-API-Key: <key>）， 且 Key 没有多余空格。Key 区分大小写。

提示 403 需要 admin 权限

当前 Key 是 user 角色，不能改连接配置。查询与看日志不受影响；需要改配置请找管理员。

提示「无法连接 MySQL / Doris / Redis / MongoDB」

服务端到数据库的网络或口令有问题。管理员可在「连接」页点「测试」看具体报错（例如 ECONNREFUSED 表示端口不通）。

结果被截断 / 只返回了一部分

命中服务端行数上限 limits.maxRows。请缩小查询范围（加 WHERE、limit、时间过滤），或让管理员调高上限。

谁调用过、调了什么？

看「日志」页：每条记录都有调用者（user）、工具、目标连接、耗时、行数、成功/失败，并支持按条件筛选与实时刷新。

Key 会存在哪里？

只存在你本机浏览器的 localStorage，前端不会把它发给除本服务以外的任何地方。点右上角「清除 Key」可随时移除。

怎么新增一个数据库连接？

找 admin 在「连接」页点「新增连接」，按上面「每种数据库要填什么」填好即可，保存即生效，不用重启。 user 角色看不到这些按钮，属于权限设计。

Claude Code 里显示 Failed to connect

按顺序查：① url 是否带了结尾的 /mcp；② type 是否写了 "http"（漏了会被当成 stdio 跳过）； ③ Key 是否正确、有没有多余空格；④ 在你机器上 curl http://<测试机>:8787/healthz 通不通。 详细报错看 claude mcp get infinmcp 的 Issue: 行，或会话里的 /mcp。

报 Dynamic Client Registration rejected (HTTP 404 / 405)

这是配置里漏了 Authorization 头的典型症状，不是服务端故障。客户端拿到 401 后误以为要 OAuth， 去探 /register 做动态客户端注册，于是报出这个跟数据库八竿子打不着的错。

修法：确认 MCP 配置里带了请求头 —— Claude Code 用 claude mcp add … --header "Authorization: Bearer <API Key>"； 手写配置就补上 "headers": { "Authorization": "Bearer <API Key>" }，然后重新连接。

服务端对这类探测会返回 oauth_not_supported 并说明该配什么，但根治还是把 Key 配上。

能不能通过这个服务写数据？

不能，这是设计目标。所有写操作在服务端被语法 / 命令白名单拦下，请求根本不会发到数据库。见上面「只读边界」。
